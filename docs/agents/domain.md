# Domain documentation

This repository uses a single domain context.

Before exploring, read the root CONTEXT.md and relevant decisions in
docs/adr/, when present. If absent, proceed without creating placeholders.

CONTEXT.md is a domain glossary, not an implementation specification.
Use its canonical terms when writing issues, tests, and documentation.

Create glossary entries when terms are resolved. Record architectural
decisions only when a meaningful tradeoff warrants an ADR.

Surface conflicts with existing ADRs explicitly rather than silently
overriding them.
